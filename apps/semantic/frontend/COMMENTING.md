# 前端注释规范

以后新增或修改前端代码时，遵循以下规则：

1. 每个支持注释的源码文件开头写明 `Description`、作用、优点、调用/被调用和简短基础知识。
2. 每个具名函数、React 组件、Hook 回调或对外暴露的 API 方法前写一条简短用途注释。
3. 注释解释“为什么存在、负责什么”，不逐行复述代码。
4. `package.json`、`tsconfig.json`、lockfile 等 JSON/生成文件不添加注释，因为会破坏格式或被工具覆盖。

推荐文件头模板：

```ts
/**
 * Description: 文件的一句话描述。
 * 作用: 文件负责的核心工作。
 * 优点: 这种拆分或实现方式的主要好处。
 * 调用/被调用: 它依赖谁，又由谁使用。
 * 基础知识: 阅读本文件前值得了解的一个概念。
 */
```

推荐函数模板：

```ts
/** 简短说明函数接收什么、完成什么或返回什么。 */
```
