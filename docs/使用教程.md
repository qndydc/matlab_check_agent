# MATLAB 代码理解与迁移：完整使用教程

本文对应当前仓库实现，命令以 Windows PowerShell 为例。除特别说明外，均在仓库根目录执行：

```powershell
Set-Location D:\Aprojet\py\matlab_check_agent
```

## 1. 先分清两个子项目

| 子项目 | 负责什么 | CLI | 开发前端 | 后端 |
| --- | --- | --- | --- | --- |
| Semantic（项目静态分析） | 扫描、代码树、调用图，以及可选函数/文件/项目三级语义 | `scan`、`analyze`、`annotate` | `http://127.0.0.1:5173` | `http://127.0.0.1:8000` |
| Migration（代码迁移） | 复用项目静态分析，按 WCC 转换 Python、检查、冻结与续跑 | `migrate` | `http://127.0.0.1:5174` | `http://127.0.0.1:8001` |

两者共用一个 Python 包和 `matlab-refactor` 总入口，不需要分别安装后端。
5173 的 **项目静态分析** 是两套页面共用的前置阶段：它保存扫描、解析和调用图 artifact；5174 新建 Web 迁移时从下拉框选择这个快照，**不会再次执行 Scanner / Parser / Analyzer**。
迁移不要求先生成三级语义；如果所选快照已经有三级语义，5174 会自动将它作为增强上下文。
5174 的 **WCC 结构** Tab 只是当前迁移任务的调用链查看器，不是第二个“项目分析”功能。

重要边界：当前默认迁移会生成代码，并检查 Python 语法与相对 import。
它**不会自动启动 MATLAB，也不会自动执行生成的 Python 或数值差分**。
`completed` / `frozen` 只表示当前已配置检查通过，不表示迁移代码已经可用于生产。
运行测试与差分执行器留有注入接口，Web/CLI 还没有配置这些执行器的开关。

## 2. 首次安装

需要 Python 3.10+（可用 3.11）、Node.js（Docker 构建使用 22）和 pnpm。
已有可用 Python 环境可以直接使用，不必重复创建。

```powershell
# 可选：新建独立环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 安装后端和测试依赖
python -m pip install -e ".[dev]"

# 两套前端分别安装
pnpm --dir apps/semantic/frontend install
pnpm --dir apps/migration/frontend install

# 仅在 .env 不存在时复制，避免覆盖已有密钥和配置
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

如 PowerShell 不允许激活虚拟环境，可以直接使用
`.\.venv\Scripts\python.exe` 执行后文的 Python 命令，CLI 则使用
`.\.venv\Scripts\matlab-refactor.exe`，不需要修改系统执行策略。

检查安装：

```powershell
python --version
node --version
pnpm --version
matlab-refactor --version
matlab-refactor --help
```

## 3. 配置 `.env`

普通扫描/调用图不需要密钥。`annotate`、`migrate` 和网页对应操作需要有效模型配置，可能产生模型费用，并会把相关 MATLAB 源码发送给配置的模型服务。

打开 `.env`，按实际服务填写：

```dotenv
# 密钥值仅填写在你本机；这里不提供真实密钥
DEEPSEEK_API_KEY=
MATLAB_REFACTOR_LLM_API_KEY_ENV=DEEPSEEK_API_KEY
MATLAB_REFACTOR_LLM_BASE_URL=https://api.deepseek.com
# 使用你实际可调用的模型 ID；模板值不代表已验证你的账号权限
MATLAB_REFACTOR_LLM_MODEL=deepseek-v4-pro

MATLAB_REFACTOR_INPUT_PATH=tests/fixtures/matlab_projects/basic
MATLAB_REFACTOR_ARTIFACT_DIR=var/jobs
MATLAB_REFACTOR_STATE_DB=var/refactor-agent.db
MATLAB_REFACTOR_WEB_DB=var/web-projects.db
MATLAB_REFACTOR_LOG_LEVEL=INFO
DEBUG_MODEL=False
```

配置优先级：**进程环境变量 > `.env` > 默认值**。
相对路径以进程工作目录为基准，因此建议一直从仓库根目录启动。
一键脚本会自动将后端工作目录设为仓库根目录。
可用 `MATLAB_REFACTOR_ENV_FILE` 指定另一份配置文件。
模型设置在下次任务或续跑开始时自动读取；存储目录、数据库路径、启动环境变量有变更时才需要重启服务。

其他常用配置：

| 配置 | 作用 |
| --- | --- |
| `MATLAB_REFACTOR_EXCLUDE_PATTERNS` | 扫描排除目录，JSON 数组，例如 `[".git", "slprj", "build"]` |
| `MATLAB_REFACTOR_ENTRY_POINTS` | 显式指定入口，JSON 数组；需匹配分析结果中的函数标识 |
| `MATLAB_REFACTOR_GRAPH_OUTPUT_DIR` | `analyze` 图文件目录，默认 `var/graphs` |
| `MATLAB_REFACTOR_AUTO_EXPORT_GRAPHS` | 是否自动导出 Graph JSON 和 Mermaid，默认 `true` |
| `MATLAB_REFACTOR_MAX_WORKERS` / `MATLAB_REFACTOR_PARSER_CHUNK_SIZE` | 确定性解析并发与分块大小 |
| `MATLAB_REFACTOR_MAX_AGENTS` | LLM 并发上限；语义文件级聚合及 WCC 内同依赖波次的 ActChunk 共用，默认 `4` |
| `MATLAB_REFACTOR_MIGRATION_MAX_AGENTS` | 同时执行的 WCC 数；固定为 `1`，避免整条大调用链并发挤占模型 |
| `MATLAB_REFACTOR_SEMANTIC_TOKEN_BUDGET` | 语义单元的目标输入预算 |
| `MATLAB_REFACTOR_SEMANTIC_MAX_FUNCTIONS_PER_UNIT` | 普通语义单元的函数数目标 |
| `MATLAB_REFACTOR_SEMANTIC_CONFIDENCE_THRESHOLD` / `MATLAB_REFACTOR_SEMANTIC_MAX_ATTEMPTS` | 语义自检阈值与尝试上限 |
| `MATLAB_REFACTOR_SEMANTIC_MAX_OUTPUT_TOKENS` | 语义模型响应输出上限 |
| `MATLAB_REFACTOR_MIGRATION_MAX_OUTPUT_TOKENS` | 转换代码响应输出上限 |
| `MATLAB_REFACTOR_LLM_CONTEXT_WINDOW_TOKENS` / `MATLAB_REFACTOR_LLM_CONTEXT_SAFETY_MARGIN_TOKENS` | 模型上下文窗口及预留余量，须按真实模型设置 |
| `MATLAB_REFACTOR_LLM_TIMEOUT_SECONDS` | 单次模型请求超时 |
| `MATLAB_REFACTOR_LLM_SDK_MAX_RETRIES` / `MATLAB_REFACTOR_LLM_RESPONSE_RETRIES` | 请求重试与结构化响应重试 |
| `MATLAB_REFACTOR_LLM_TEMPERATURE` / `MATLAB_REFACTOR_LLM_THINKING_MODE` | 模型参数；须与提供方兼容 |
| `DEBUG_MODEL` | Agent 详细调试总开关；`True` 时在后端终端和网页进度区显示语义注释、模型调用和 WCC 迁移细节，默认 `False` |

`.env.example` 已移除未被当前实现读取的旧配置，如 `CHECKPOINT_DB`、`MAX_REPAIR_ATTEMPTS`、`CODE_OUTPUT_DIR`。
迁移断点是 Job 目录中的 JSON 文件，不是另一个 LangGraph SQLite 库。
请不要把输出目录设在被分析的 MATLAB 项目内部。

### 3.1 在网页中设置模型（两个应用通用）

启动 Semantic 或 Migration 后，点击右上角 **设置**：

1. 填写模型名称和 **API Base URL**。URL 是兼容接口的根地址，例如 `https://your-provider.example/v1`，不要填成 `/chat/completions`，也不要把密钥放在 URL 中。
2. 输入 API Key；已保存的密钥只显示“已配置”，不会回传明文。**留空保留原密钥**，输入新值替换；勾选“清除已保存的 API Key”并保存才会清除本地配置，不会撤销模型提供方的密钥。
3. 按需展开“高级参数”，调整请求超时、网络/结构化响应重试、温度、思考模式、上下文窗口和安全余量、语义/迁移输出上限，以及语义单元预算、函数数、置信度和尝试次数。不支持 `thinking` 参数的提供方可选“不发送此参数”。
4. 点击 **保存配置**。参数范围及 token 预算会在后端校验，不合法时整次修改都不写入。保存不会调用模型或验证账号权限。
5. 新任务、点击“生成三级注释”或“续跑未完成 WCC”时读取新配置；已经执行中的任务继续使用原配置，已冻结 WCC 不会因换模型而重新转换。CLI 下次启动也会读取同一份 `.env`。

两套应用共用一个设置组件和配置接口，不另外维护一份前端配置。它们指向同一份 `.env` 时修改互通；已经打开的另一个面板需点击“重新加载”。两边同时保存时，过期版本会提示重新加载，避免覆盖彼此的修改。面板底部显示实际配置路径。

密钥写入 `MATLAB_REFACTOR_LLM_API_KEY_ENV` 指定的变量（默认 `DEEPSEEK_API_KEY`）；变量名本身在 `.env` 中配置，不由网页任意更改。`.env` 中的 `${...}` 按字面量读取，不做变量插值，避免破坏包含特殊字符的密钥。

**显示“由进程环境控制”的字段是只读的**：启动环境变量优先级更高，不能通过写 `.env` 假装覆盖。需要修改终端、IDE 或容器的启动环境并重启服务。目录、数据库、入口和解析器参数仍在 `.env` 中编辑，不开放到模型面板，避免误改断点存储位置。

安全提醒：`.env` 仍是本地明文文件，密钥不会返回 API 响应，也不会写入浏览器存储。不要提交 `.env`，不要把本应用暴露到公网。更改 URL 会改变后续源码与密钥发送到的服务，请只填写可信地址；HTTP 仅适用于可信本地环境。

## 4. 最简单的启动方式：一键启动

语义应用：

```powershell
python scripts/start_mvp.py
```

访问 `http://127.0.0.1:5173`。

迁移应用：

```powershell
python scripts/start_migration.py
```

访问 `http://127.0.0.1:5174`。

需要同时使用两套应用时，在两个终端分别运行这两条命令。
启动器会检查端口、等待后端健康检查，并监控前后端进程。
在各自终端按 **Ctrl+C** 会停止对应的前后端，不会删除历史任务和产物。
不要在相同端口重复启动一键脚本和单独的后端命令。

终端 A，在仓库根目录启动后端：

```powershell

```

终端 B，启动前端：


### 5.2 Migration

终端 A，在仓库根目录启动后端：

```powershell

```

终端 B，启动前端：

```powershell
pnpm --dir apps/migration/frontend dev --host 127.0.0.1 --port 5174 --strictPort
```

前端 Vite 会代理 `/api` 到对应的 `8000` / `8001` 后端。
若修改后端端口，还要修改相应 `vite.config.ts` 中的代理目标。

### 5.3 后端入口的全部等价形式

| 用途 | 命令 |
| --- | --- |
| 语义后端 | `matlab-semantic-web` |
| 语义后端兼容旧入口 | `matlab-refactor-web` |
| 语义后端 Python 模块入口 | `python -m matlab_refactor_agent.apps.semantic.backend.main` |
| 迁移后端 | `matlab-migration-web` |
| 迁移后端 Python 模块入口 | `python -m matlab_refactor_agent.apps.migration.backend.main` |

这些入口默认不输出每次轮询的 HTTP 访问日志。
想自行指定 Uvicorn 参数时，可以使用：

```powershell

python -m uvicorn matlab_refactor_agent.apps.migration.backend.app:app --host 127.0.0.1 --port 8001 --no-access-log
```

迁移后台任务采用本地单进程模式，请勿添加多 worker 参数，也不要在运行迁移时使用自动重载。

## 6. Semantic 网页怎么用

1. 输入本机 MATLAB 项目文件夹，例如 `D:\MATLAB\signal_project`。
2. 点击 **项目静态分析**：扫描 `.m` 文件，构建代码树、调用关系、SCC、入口和未解析调用。这也是 5174 可复用的公共前置阶段。
3. 点击目录、文件或函数查看结构；可以搜索和查看函数源码。
4. 在右上角“设置”配置模型、URL 和 API Key（见 3.1），再点击“生成三级注释”，生成函数 → 文件 → 项目三级说明。
5. 顶部监控默认折叠，只显示当前阶段；展开后查看最近 12 条事件和错误详情。
6. 从历史项目恢复已保存的图和语义，不必为了浏览再次调用模型。

语义 Web 使用 `var/web-projects.db` 保存项目历史；核心流水线仍在 `var/jobs` 保存原始产物。5174 会通过语义 Web 项目 ID 在 SQLite 中找到对应的 scan / analysis artifact 引用；这个 ID 只是“项目静态分析快照 ID”，**不是**迁移 Job ID，也不能用于迁移断点续跑。
历史中没有“可复用项目静态分析”标记的旧记录缺少 artifact 引用，不能自动升级；请在 5173 对该项目再执行一次项目静态分析。

**当前没有 `annotate --resume` 命令。** 语义历史浏览、单次运行中的有限重试、跨进程按函数簇续跑是不同概念；不要将已有结果存盘理解为自动跳过已注释簇。

## 7. Migration 网页怎么用

首次使用先打开右上角“设置”，确认模型、URL、API Key 和迁移输出预算。已在 Semantic 设置过同一份 `.env` 时，无需重复填写。

1. 先在 5173 对同一个项目完成 **项目静态分析**。两个后端必须使用同一份 `.env`，特别是相同的 `MATLAB_REFACTOR_WEB_DB` 和 `MATLAB_REFACTOR_ARTIFACT_DIR`。
2. 在 5174 的 **PROJECT STATIC ANALYSIS · 5173** 下拉框选择可用快照。若快照含三级语义，会自动带入；不再手填 `semantic-index.json`。
3. 点击“开始迁移”。后端会先校验快照 artifact 和 MATLAB 源码指纹，再创建独立的迁移 Job；校验通过后直接从 WCC 计划开始，不重复扫描、解析或分析。关闭网页不会停止后端任务。
4. 快照显示“需刷新”通常表示 MATLAB 源码、artifact 路径或旧记录已变化；回到 5173 重新执行项目静态分析后再选它。
5. 左侧显示 WCC 队列。SCC 是 WCC 内不可拆分的原子；图中每个 SCC 节点的状态沿用其 WCC 状态。
6. **WCC 结构 Tab**：查看选中 WCC 的入口、SCC 组成、调用边与自动带入的可选三级语义。
7. **迁移 Tab**：查看同一 WCC 的 Reason 策略、Observation、转换尝试和生成的 Python 文件。
8. 点击其他 WCC 或切换 Tab，选择会联动；刷新网页后可从历史任务重新打开结果。
9. 顶部进度是“已冻结 WCC 数 / 总 WCC 数”，不是模型 token 进度或预计剩余时间。
10. 运行日志默认折叠，展开只显示最近 12 条阶段摘要和产物目录；不把模型提示词、源码或长 JSON 混入日志区。

任务状态：

| 状态 | 含义 / 下一步 |
| --- | --- |
| `queued` | 等待后台执行；当前后端串行处理迁移任务 |
| `running` | 正在分析或执行 WCC 循环 |
| `completed` | 全部 WCC 已冻结；仍需按项目需求做运行和数值验收 |
| `failed` | 执行异常；查看短错误，修复环境后有断点可续跑 |
| `interrupted` | 服务退出后留下的未完成任务；不会自动调用模型，需手动续跑 |
| `manual_review` | Reason 无法可靠继续或结构需要复核；先检查具体问题 |

“历史任务”列出由迁移 Web 提交的任务。纯 CLI 任务目前不会自动出现在该下拉框。
“刷新连接 / 历史”可在后端重新启动后重连；页面轮询失败时也会尝试重新读取当前任务。
预览最多显示每个文件前 100,000 个字符，完整文件保存在磁盘产物目录。

### WCC 断点续跑

在历史任务中选择原任务，点击 **“续跑未完成 WCC”**：

```text
同一 Job ID
  已 frozen 的 WCC → 直接跳过，原产物保留
  未完成的 WCC     → 从 Build Context 重新开始
```

这不是恢复到模型输出到一半的位置，而是恢复到 WCC 边界。
续跑会继续增加尝试编号，旧上下文、策略、转换响应与生成目录不会被覆盖。
运行中任务不能重复续跑；全部完成后按钮禁用。
如果失败发生在迁移断点创建前（例如没有模型密钥），修复配置后需新建任务。
源码与扫描快照不匹配时拒绝续跑；增加文件、改变入口/排除规则或改用另一语义索引，也应新建任务。
当前源码指纹覆盖扫描快照内的 `.m` 文件，不覆盖图片、数据文件或新增的未扫描文件。

## 8. 全部业务 CLI

所有命令共用 `matlab-refactor`，不依赖 Web 服务，也不需要先启动前端。
若命令不在 PATH 中，可用 `python -m matlab_refactor_agent` 替换 `matlab-refactor`。

### 8.1 扫描

```powershell
matlab-refactor scan "D:\MATLAB\signal_project"
matlab-refactor scan "D:\MATLAB\signal_project" --json var/scan.json
```

发现并解析 `.m` 文件，提取函数、脚本和参数等元数据，不调用模型。

### 8.2 结构分析

```powershell
matlab-refactor analyze "D:\MATLAB\signal_project"
matlab-refactor analyze "D:\MATLAB\signal_project" --tree
matlab-refactor analyze "D:\MATLAB\signal_project" --json var/analysis.json --graph-json var/graph.json --mermaid var/calls.mmd
```

`--tree` 在终端展示依赖树；`--graph-json` 导出节点/边；`--mermaid` 导出图文本。
默认还会按 Job ID 自动导出两类图到 `var/graphs`，可通过配置关闭。

### 8.3 三级语义

```powershell
matlab-refactor annotate "D:\MATLAB\signal_project"
matlab-refactor annotate "D:\MATLAB\signal_project" --json var/semantic-export.json
```

输出完整 SemanticIndex；普通结构分析与三级语义生成仍是两个独立步骤。
自动保存的标准索引为 `var/jobs/<内部Job ID>/semantic-index.json`。

### 8.4 MATLAB → Python 迁移

```powershell
# 不使用语义索引
matlab-refactor migrate "D:\MATLAB\signal_project"

# 使用上一步导出的索引；CLI/Web 都会复制一份到新 Job
matlab-refactor migrate "D:\MATLAB\signal_project" --semantic-index var/semantic-export.json

# 导出迁移结果：计划、生成响应与产物引用，不是单个 Python 程序
matlab-refactor migrate "D:\MATLAB\signal_project" --json var/migration-result.json
```

CLI 是自包含入口：会执行项目静态分析 → WCC 计划 → Context → Reason → Act → Assemble → Observe → 重试/冻结/人工复核。它不依赖 5173 已保存的 Web 快照；5174 的“复用静态分析”仅适用于 Web 工作流。
项目级发布与自动打包不是当前命令的承诺。

### 8.5 续跑同一迁移任务

以下示例中的 ID 请替换为自己任务输出的真实 Job ID：

```powershell
matlab-refactor migrate --resume "这里替换为任务ID"
matlab-refactor migrate "D:\MATLAB\signal_project" --resume "这里替换为任务ID"
matlab-refactor migrate --resume "这里替换为任务ID" --json var/resumed-result.json
```

第一种读取断点里的原项目路径；第二种额外校验路径匹配。
`--resume` 不能与 `--semantic-index` 同时使用，因为续跑必须沿用原任务输入。
必须保留原 Artifact 目录、状态数据库与 MATLAB 源码路径。
不要同时从 CLI 和 Web 执行同一个 Job，也不要在两个后端实例中续跑同一任务。

### 8.6 查询状态和帮助

```powershell
matlab-refactor status "这里替换为任务ID"
matlab-refactor --help
matlab-refactor --version
matlab-refactor scan --help
matlab-refactor analyze --help
matlab-refactor annotate --help
matlab-refactor migrate --help
matlab-refactor status --help
```

`status` 查询核心 Job / Worker 状态；它不支持 `--json`，也不等同于 WCC 验收结果。
例如流程正常返回人工复核结果时，核心 Job 可以是 `completed`，而迁移 checkpoint 是 `manual_review`。
查看迁移的最终业务结论，应以 checkpoint 和各 WCC Observation 为准。

### 8.7 公共参数与退出码

| 参数 | 适用范围 | 说明 |
| --- | --- | --- |
| `[project]` | scan/analyze/annotate/migrate | 可省略，读取 `MATLAB_REFACTOR_INPUT_PATH`；续跑时改读原断点 |
| `--json FILE` | 上述四个命令 | 保存完整结果 JSON；请选新文件名，避免覆盖自己的导出文件 |
| `--json` 或 `--json -` | 上述四个命令 | JSON 写到 stdout，状态提示和日志写到 stderr |
| `--tree`、`--graph-json FILE`、`--mermaid FILE` | analyze | 依赖树与图导出 |
| `--semantic-index FILE`、`--resume JOB_ID` | migrate | 可选索引与断点，二者互斥 |

避免把 `--json` 放在尚未给出的项目路径前，因为它有可选 FILE 参数。
推荐 `matlab-refactor analyze "项目路径" --json`，或显式使用 `--json -`。
正常返回退出码为 `0`，命令参数/业务异常为 `2`，Ctrl+C 为 `130`。
`0` 不等于 MATLAB/Python 数值一致，也不排除结果中有人工复核项。

## 9. 产物在哪里，如何备份

默认结构如下；尖括号表示实际生成的编号，不要原样输入命令：

```text
var/
├── refactor-agent.db                 CLI / 核心 Job 审计
├── web-projects.db                   语义 Web 历史图与三级语义
├── graphs/                          Graph JSON / Mermaid
└── jobs/<Job ID>/
    ├── scan-result.json                静态分析 Job 才有；5174 复用时位于原快照 Job
    ├── analysis-result.json            静态分析 Job 才有；5174 checkpoint 只保存对它的引用
    ├── structural-code-tree.json
    ├── semantic-index.json           语义任务才有
    ├── input-semantic-index.json     迁移的可选索引副本
    ├── matlab-to-python-plan.json    WCC/SCC 计划
    ├── migration-web.json            Web 任务记录
    ├── migration-checkpoint.json     原项目、源码指纹、引用
    ├── migration-state.json          每条 WCC 的状态和产物引用
    ├── migration-progress.json       最近 200 条短阶段事件
    ├── context-<WCC>-<编号>.json
    ├── stratagem-<WCC>-<编号>.json
    ├── act-context-<WCC>-<尝试>.json
    ├── translation-<WCC>-<请求ID>.json
    ├── assembly-<WCC>-<尝试>.json
    ├── observation-<WCC>-<尝试>.json
    └── generated-python/<WCC>/attempt-<编号>/...
```

每条 WCC 的最新有效文件路径以 `migration-state.json` 指向的 `assembly_ref` 为准，
不要只根据目录编号挑文件：最新尝试可能还没有通过检查。
用独立 Python 环境人工检查生成文件、准备数据与依赖、确认入口后再运行；不要在存有密钥或重要数据的环境中直接执行未经审查的生成代码。

备份时先停止服务，再同时备份 `var/jobs` 和相应 SQLite 文件；更稳妥的是备份整个 `var`。
单独复制生成的 `.py` 不能用于恢复 Agent。断点使用绝对引用，不能直接把目录迁到另一台机器后就保证续跑。

## 10. 前端构建与单端口使用

两套前端的脚本相同：`dev` 开发服务、`build` 类型检查并构建、`preview` 预览已有构建。

```powershell
pnpm --dir apps/semantic/frontend build
pnpm --dir apps/migration/frontend build
```

构建后，在仓库中启动后端会自动找到对应 `dist`，无需再启动 Vite：

```powershell
matlab-semantic-web
# 浏览器访问 http://127.0.0.1:8000

matlab-migration-web
# 浏览器访问 http://127.0.0.1:8001
```

上面两条后端命令需要分别在独立终端运行。
如部署目录不同，可设置 `MATLAB_REFACTOR_FRONTEND_DIR`（语义）或 `MATLAB_MIGRATION_FRONTEND_DIR`（迁移）指向包含 `index.html` 的 dist 目录。
修改源码后必须重新 `build` 并刷新网页，旧 dist 不会自动更新。

仅预览前端构建也可以：

```powershell
pnpm --dir apps/semantic/frontend preview --host 127.0.0.1 --port 4173 --strictPort
pnpm --dir apps/migration/frontend preview --host 127.0.0.1 --port 4174 --strictPort
```

预览服务本身不会启动 Python 后端，API 功能仍需要对应后端运行。

## 11. Docker（可选）

需要 Docker Desktop 的 Linux containers 模式。现有 `.env` 不要覆盖，按 `.env.docker.example` 补充：

```dotenv
MATLAB_PROJECTS_PATH=D:/MATLAB/projects
MATLAB_DATA_PATH=D:/MATLAB/matlab-atlas-data
```

提前创建上述目录，然后执行：

```powershell
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail 30 -f semantic-app migration-app
```

语义应用访问 `http://127.0.0.1:8000`，迁移应用访问 `http://127.0.0.1:8001`。
容器模式已含前端构建，不使用 `5173/5174`。
页面可以填写容器内路径，例如 `/projects/signal_project`；也可以填写
`MATLAB_PROJECTS_PATH` 下的 Windows 完整路径，后端会自动映射到 `/projects`。
MATLAB 输入挂载只读；两个容器共享 `/data/jobs` 和状态文件，可传递显式索引路径。

在容器里使用 CLI：

```powershell
docker compose exec semantic-app matlab-refactor analyze /projects/signal_project
docker compose exec semantic-app matlab-refactor annotate /projects/signal_project
docker compose exec migration-app matlab-refactor migrate /projects/signal_project
docker compose exec migration-app matlab-refactor status "这里替换为任务ID"
```

日常管理：

```powershell
docker compose stop
docker compose up -d
docker compose restart
docker compose down
```

绑定的数据目录不会因 `down` 被删除，但仍应备份。Docker 与本机开发服务会争用 `8000/8001`，请选择一种方式运行或修改 Compose 端口。
当前服务没有登录认证，只供本机/可信环境使用，不要直接暴露公网。

Compose 根目录的 `.env` 只负责宿主机挂载路径、绑定地址和端口。模型名称、
Base URL、API Key、超时和 token 预算可在网页“设置”中修改，并持久化到
`MATLAB_DATA_PATH/config/.env`；两个容器共享该文件，新任务自动读取，不需要重建镜像。

## 12. 日志与常见问题

| 问题 | 处理 |
| --- | --- |
| 前端离线 / 请求失败 | 检查后端终端和 `/api/health`；确认 Vite 代理端口；点击“刷新连接 / 历史” |
| 端口被占用 | 停止自己先前启动的对应服务；不要直接杀死不认识的进程 |
| 找不到 `matlab-refactor` | 激活正确环境、重新 `pip install -e ".[dev]"`，或用 `python -m matlab_refactor_agent` |
| 页面路径不存在 | 本地模式填后端机器路径；容器模式填 `/projects/...` |
| 无模型密钥 / 请求超时 | 打开“设置”检查模型、URL、密钥状态和超时后重新启动任务/续跑；若由进程环境控制则修改启动环境并重启 |
| 语义索引无效 | 必须是完整 SemanticIndex，不是 graph.json、项目树或 migration-result.json；所属项目必须一致 |
| 续跑按钮不可用 | 运行中、已全部完成，或失败太早尚无 checkpoint；最后一种修复后新建任务 |
| 源码变化导致拒绝续跑 | 新建迁移任务，不要修改断点指纹来绕过校验 |
| 已冻结但程序不能运行 | 静态检查不覆盖入口参数、数据文件、第三方依赖和数值行为；需要额外人工测试 |
| 恢复后找不到产物 | 检查启动目录、ARTIFACT_DIR、STATE_DB 是否与原任务相同；不要删除或移动旧 Job 目录 |
| 日志过多 | 默认已关闭访问日志；`MATLAB_REFACTOR_LOG_LEVEL=WARNING` 可进一步减少业务终端输出；页面展开日志最多显示 12 条 |

需要临时排查模型请求时可以使用 `DEBUG`，但调试输出可能包含敏感项目内容，不要公开粘贴完整日志。恢复 `INFO` 并重启后端即可回到简洁模式。

```powershell
python -m pytest
```


pytest 会清理它的 `--basetemp`，每次请选仅用于测试的目录，不要指向真实任务产物。
迁移 Web 集成测试使用模拟 LLM，但扫描、WCC、LangGraph、文件组装、检查和断点都是实际实现，不需要付费密钥。

| 入口 | 分工 |
| --- | --- |
| `interfaces/cli/main.py` | 只解析参数和分发 |
| `interfaces/cli/commands.py` | 五个 CLI 命令的业务处理 |
| `application/semantic_service.py` / `migration_service.py` | 两个子项目的用例门面 |
| `apps/migration/backend/app.py` | 薄 API 路由和静态前端挂载 |
| `apps/migration/backend/jobs.py` | 后台任务、历史/续跑、把真实产物转为前端视图 |
| `migration/agent.py` | 组合会话、运行组件和图 |
| `migration/checkpoint.py` / `runtime.py` | 断点生命周期 / 各 WCC 运行组件与简短阶段日志 |
| `orchestration/migration_graph.py` | Reason → Act → Observe 的路由 |
| `apps/migration/frontend/src/App.tsx` | 双 Tab、任务队列、日志和结果视图 |

完整调用关系：网页 → API → 后台任务管理 → MigrationService → 原有 WCC Agent。
CLI 直接调用同一个 MigrationService，前端没有复制一份转换逻辑。
