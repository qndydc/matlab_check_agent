# 结构图拆分算法

## 目标与边界

结构分析负责回答四个问题：项目里有什么、函数定义在哪里、函数之间怎样调用、哪些部分适合作为后续语义和迁移的工作单元。

该阶段完全确定性运行，不调用 LLM。相同源码和配置应得到相同的扫描清单、符号表、调用边、SCC/WCC 和代码树。

## 总体流程

```text
MATLAB 项目根目录
  → 扫描 .m 文件
  → 分块解析脚本、函数、局部函数和类方法
  → 构建全局/文件内符号索引
  → 解析显式调用并记录未解析调用
  → 构建有向调用图
  → 计算入口、孤立点、SCC 与 WCC
  → 生成项目/目录/文件/函数结构树
```

公共入口为 `matlab_refactor_agent.analysis.AnalysisPipeline`。

## 1. 文件扫描

Scanner 从项目根目录递归发现 `.m` 文件，并应用排除规则。默认排除 Git、依赖、构建和生成目录；测试夹具和用户规则可以补充排除项。

扫描输出至少记录：

- 相对文件路径和内容指纹；
- 文件大小与解析状态；
- 配置的入口和排除规则；
- 可供断点恢复校验的文件清单。

后续阶段只处理扫描清单内文件，避免迁移 Agent 临时扩大仓库读取范围。

## 2. MATLAB 解析

Parser 使用 AST 提取：

- 脚本和主函数；
- 同文件局部函数；
- package 函数和 class method；
- 输入/输出参数；
- 定义起止行和调用点。

AST 失败时才使用受限的正则降级，并明确保留诊断，不能把降级结果伪装成完整解析。

函数使用稳定 `symbol_id` 标识。局部函数带文件作用域，package/class 成员保留限定名，避免仅按短函数名错误合并。

## 3. 调用边解析

对每个调用点按从具体到一般的顺序匹配：

1. 调用者所在文件的局部函数；
2. 完整限定名；
3. 项目内唯一短名称；
4. 无唯一候选时记录为 unresolved call。

解析结果形成有向边 `caller → callee`。未解析调用继续保留调用者、文件和位置，用于前端提示与迁移人工复核，而不是被静默删除。

## 4. 入口、孤立节点和循环

- 显式配置的入口优先；
- 未配置时根据主函数、脚本和入度推断候选入口；
- 没有有效连接的函数标记为孤立节点；
- 强连通分量算法用于识别 SCC；
- SCC 内任意节点互相可达，因此迁移时将其视为不可拆原子。

调用图可压缩成 SCC DAG。这个 DAG 没有环，可用于语义工作单元排序和迁移依赖调度。

## 5. 两种拆分尺度

### SCC：循环依赖原子

SCC 解决“哪些函数不能安全地独立排序”。单函数也是一个平凡 SCC；包含多个函数或自环的 SCC 是循环簇。

### WCC：完整调用链上下文

忽略调用边方向后计算弱连通分量（WCC）。一个 WCC 汇集彼此有关联的一组 SCC，是迁移的主要上下文和验收单位。

```text
项目调用图
├── WCC A
│   ├── SCC A1（入口）
│   ├── SCC A2（循环簇）
│   └── SCC A3
├── WCC B
└── 孤立 WCC C
```

语义 Pipeline 可以在 SCC/邻居基础上按 token 预算进一步组合；迁移 Agent 以 WCC 保持端到端上下文，再在 WCC 内按 SCC DAG 生成 ActChunk。

## 6. 分级结构树和前端图

Analysis 同时生成两种视图：

- `structural-code-tree.json`：project → directory → file → symbol 的稳定层级；
- Graph Document：函数节点与调用边，以及循环、入口、孤立和 unresolved 标记。

前端不会一次发送和渲染整个大型图。`graph_view.py` 根据 scope、focus、depth、direction 和 limit 生成渐进视图：

```text
项目总览 → 目录依赖 → 文件依赖 → 函数调用者/被调用者邻域
```

完整图仍保存在后端，视图裁剪不改变分析事实。

## 标准产物

```text
file-manifest.json
scan-result.json
analysis-result.json
structural-code-tree.json
graph.json / calls.mmd（按配置导出）
```

这些产物是三级语义和迁移的共同输入。后续模型输出只能引用它们，不能覆盖它们。

## 复杂度与扩展点

设函数数为 `V`，调用边数为 `E`。构图和 SCC/WCC 计算主要为 `O(V + E)`；实际耗时通常由文件读取和解析主导。解析按文件分块并行，但最终聚合保持确定顺序。

后续可扩展动态调用候选、函数句柄传播、Simulink 关系和增量文件监听。新增推断必须携带置信度/诊断，并与确定性显式调用边区分。
